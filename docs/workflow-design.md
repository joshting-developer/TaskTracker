# 日常任務工作流程

## 2026-11-05 詳細頁工時入口

任務完整頁的「工時」分頁現在可填報，也可修改自己的有效紀錄。Task／Bug直接帶入目前任務並鎖定；Epic入口只選其所屬執行卡。表單沿用月曆的右側抽屜，工作日期預設今天（Asia/Taipei）；保存後留在原頁，紀錄與加總重新取得，月曆呈現同一筆資料。

月曆與詳細頁共用`TimeEntryDrawer`，填報與修改依`timeEntry.writeOwn`，讀取依原有工時讀取權限；不是擁有任務編輯權就自動放行。管理者也不能修改別人的紀錄。表單保留分鐘驗證、每日24小時限制、requestId防重複、修改原revision與離開保護。背景刷新不能重置草稿與版本，409時取消編輯後重新選最新紀錄；撤權清除抽屜。月曆點日期填報及本人修改／作廢路徑繼續保留。

## 2026-11-05 詳細頁側欄分區

右側改成「屬性／關聯」兩個真正切換內容的tab。屬性預設顯示類型、優先級、負責人、期限與工時；關聯按所屬Epic、父任務、Epic所屬卡片／子任務及一般關聯分組，顯示編號、標題及狀態，點卡片開啟完整頁。主文移除原關聯清單，專注描述及留言／異動／工時。

側欄清單有獨立捲動範圍，長Epic不撐開主文標題與描述間距；空集合顯示「尚無關聯卡片」。手機預設收合，以「屬性與關聯」展開同一組tab，保留原本閱讀優先順序。tab有aria-controls／aria-labelledby／roving tabindex，方向鍵及Home／End沿用共用helper；切換不丟失留言草稿。修改關聯仍用既有編輯任務，不新增第二套寫入入口。

工程驗證：build及隔離登入畫面檢查通過；以21張卡片的Epic確認清單能捲到最後，一般Task確認所屬Epic／子任務／關聯，子任務確認父項連結、空狀態、鍵盤及切tab保留留言，1440／768／390px皆無整頁橫向溢位。完整真實API瀏覽器與UIUX回歸皆通過，包含唯讀／撤權、狀態與留言衝突、列表／看板返回、手機收合及鍵盤操作。

沿用兩個UI／UX skill的單元件／app-screen流程；保留品牌與字型。已登入頁面用Taste量測模組配合Playwright，另人工檢視Task／Epic三種尺寸，沒有宣稱完整上游inspector通過。既有編輯按鈕陰影FAIL及品牌代碼／字型fallback等WARN屬既有樣式，未擴張成本輪整頁改版。證據在`/tmp/tasktracker-sidebar-ui/`與`/tmp/tasktracker-sidebar-{build,browser,lint}.log`；測試只用隔離SQLite人造資料。

列表的任務欄只顯示標題與編號，保留其他主要欄位、閱讀及快速編輯入口；Epic、父子／關聯摘要、工時、留言數及每列重複的專案名稱收掉。完整資料繼續保存在後端，點標題進詳細頁即可查看；搜尋、Epic／關聯等篩選及看板維持既有功能。

以同一組人造任務量測，1440／768／390px的樣本列高由96／148／120px降為72／72／70px，三種尺寸無整頁橫向溢位。build與登入後詳細頁子任務／關聯／工時驗證通過；完整真實隔離API瀏覽器回歸通過，含從精簡列表閱讀父任務、快速編輯、篩選、看板與手機。

## 看板列表與收錄（2026-10-20）

專案內「任務看板」先進看板列表。Default 是固定的目前專案全部卡片看板；自訂看板可選 Epic 或一般卡片, 選 Epic 時動態帶入所屬卡片, 後續新增或移動也會反映。單卡明確收錄獨立於 Epic, 重複不增加張數。看板內新增卡片同交易收錄, 移除看板或解除收錄都不刪卡

看板使用目前專案狀態欄, 即時篩選與收錄取交集；一般父 Task／Bug 不隱含收錄子任務。詳細頁、重整與返回保留 Default／自訂位置, 舊 /board 網址仍開 Default。完整契約與權限規則見[看板設計](board-design.md)

## Issue 類型（2026-10-20）

目前固定 Epic、Task、Bug, 顯示名稱與表單／篩選一致。Epic 是彙總容器, Task／Bug 是可填工時的執行卡, 可有子任務／關聯；列表及看板仍不混入 Epic 卡片。Feature 已取消, migration `2026_10_20_000001_simplify_issue_types` 改為 Task, 原資料與歷史保留, 增加一次 revision 與轉換紀錄, 重跑不再更動。舊版匯入沿用升級器；回舊版需還原升級前備份, 不猜測哪些 Task 原本是 Feature。自訂類型僅列未來討論, 本輪不實作

## 子任務與關聯任務（2026-10-20 取代前置依賴）

使用者明確要求改成子任務及關聯任務, 取消前置任務。`blockedBy`、DAG、未完成前置阻止結案、重開後依賴提示及 blocked／review 篩選已退役, 不再提供可選依賴模式

- `parentIssueId` 保存同專案一般任務的父項, Task／Bug 各自仍是可指派、可填估時／工時的 Issue。只提供一層, 不允許自我、循環、子任務再當父項或 Epic 當一般父項
- 從父任務直接新增子任務, 也可在既有任務選擇／解除父任務。父項顯示子任務完成數, 狀態各自管理, 不自動結案／重開父項, 不阻止一般父任務結案
- 子任務繼承父項的 Epic。父項改 Epic 時, 同一交易同步子項 Epic、revision 與 history；子項不能在看板自行換到另一個 Epic 泳道, 應改父項或先解除父子關係
- 一般父項的估時／工時只代表自身, 子項各記各的。Epic 按所有實際歸屬 Issue 各加一次, 不加總任何已包含子項的父項彙總數。既有 Epic 人工驗收及取消分類語意沿用
- `relatedIssueIds` 表示無方向的一般關聯, 可連同專案其他 Issue（含 Epic）, 不連動狀態。建立／解除在同一交易同步兩端 revision／history, 同一對不能重複、自我或跨專案連結；來源版本檢查避免舊表單覆寫, requestId 重試不重做異動
- 由 Workspace namespace、Project scope 與有效 issue.write 權限限定讀寫, 不以角色名稱放行

### 舊資料升級

Laravel migration `2026_10_20_000000_replace_issue_dependencies` 將既有有效 blockedBy 邊改為雙向一般關聯, 不推測父子。Issue ID、狀態、作者及歷史保留, 新增系統升級 history 並增加 revision, 防止舊表單續寫。原前置 ID 留在歷史, 無效或跨專案目標不變成新關聯。重跑不重複轉換；之後匯入舊 Node SQLite 也呼叫同一升級器, 來源仍唯讀

升級前用 SQLite 備份保存原資料庫, 自動 down 不會推測恢復依賴方向, 回舊版本需還原升級前備份。原本已保存的 blocked／review 視圖紀錄原地保留；視圖功能已依下節移除, 目前不回傳或套用這些條件

## 即時篩選與視圖停用（2026-10-20）

使用者已要求移除視圖功能, 目前只保留專案內即時搜尋、狀態／優先級／負責人／Epic／類型／情況篩選與排序。條件採 AND, 收合篩選時顯示條件摘要, 可逐項移除或全部清除。情況提供尚未結案、逾期與未指派；逾期只含未結案且到期日早於今天, 取消不列為逾期。我的任務範圍也與其他條件相交

已移除保存、命名、套用、更新、分享及刪除視圖介面與 RPC, getWorkspace 不回傳 savedViews, Seed 不再建立它。既有紀錄留在資料庫, 不作破壞性清除, 不當作仍提供的功能。舊 `?view=` 參數會被移除並提示停用, 原專案／看板／Issue 路徑仍可開啟；不讀取舊條件或用它切換列表與看板
