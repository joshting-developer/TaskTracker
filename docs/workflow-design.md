## 子任務與關聯任務（2026-10-20 取代前置依賴）

使用者明確要求改成子任務及關聯任務, 取消前置任務。`blockedBy`、DAG、未完成前置阻止結案、重開後依賴提示及 blocked／review 篩選已退役, 不再提供可選依賴模式

- `parentIssueId` 保存同專案一般任務的父項, Task／Bug／Feature 各自仍是可指派、可填估時／工時的 Issue。只提供一層, 不允許自我、循環、子任務再當父項或 Epic 當一般父項
- 從父任務直接新增子任務, 也可在既有任務選擇／解除父任務。父項顯示子任務完成數, 狀態各自管理, 不自動結案／重開父項, 不阻止一般父任務結案
- 子任務繼承父項的 Epic。父項改 Epic 時, 同一交易同步子項 Epic、revision 與 history；子項不能在看板自行換到另一個 Epic 泳道, 應改父項或先解除父子關係
- 一般父項的估時／工時只代表自身, 子項各記各的。Epic 按所有實際歸屬 Issue 各加一次, 不加總任何已包含子項的父項彙總數。既有 Epic 人工驗收及取消分類語意沿用
- `relatedIssueIds` 表示無方向的一般關聯, 可連同專案其他 Issue（含 Epic）, 不連動狀態。建立／解除在同一交易同步兩端 revision／history, 同一對不能重複、自我或跨專案連結；來源版本檢查避免舊表單覆寫, requestId 重試不重做異動
- 原型仍由 Workspace namespace 限定存取及集中 issue.write 授權, 未完成的 Project ACL 仍屬已知限制, 不以角色名稱放行

### 舊資料升級

Laravel migration `2026_10_20_000000_replace_issue_dependencies` 將既有有效 blockedBy 邊改為雙向一般關聯, 不推測父子。Issue ID、狀態、作者及歷史保留, 新增系統升級 history 並增加 revision, 防止舊表單續寫。原前置 ID 留在歷史, 無效或跨專案目標不變成新關聯。重跑不重複轉換；之後匯入舊 Node SQLite 也呼叫同一升級器, 來源仍唯讀

升級前用 SQLite 備份保存原資料庫, 自動 down 不會推測恢復依賴方向, 回舊版本需還原升級前備份。已保存的 blocked／review 視圖保留原條件並提示失效, 回傳空結果, 使用者明確改選條件後才能更新視圖；不把舊查詢悄悄放寬

## 常用篩選（原常用視圖）

將目前專案的搜尋、狀態、優先級、成員、Epic、類型、特殊條件與排序保存。日常可以快速切「我的未完成 Bug」「待測試」「逾期」, 不用反覆設定

視圖只保存查詢條件, 不複製 Issue／工時, 結果永遠根據最新資料。預設個人使用, 可明確選擇分享給目前工作空間的專案成員

- 個人視圖只有作者可讀；團隊視圖成員可讀, 只有作者可修改／刪除
- 每個視圖綁專案與作者, 查詢、異動和 requestId 都在工作空間內隔離
- 保存 ID 與固定欄位, 不接受可執行查詢或任意 SQL；多條件採 AND
- 刪除採封存, 重試不產生第二次操作, 不能透過 requestId 讀取其他人的私有視圖
- 重新整理保留選用的視圖, 網址可分享團隊視圖；無權讀取或無效連結不顯示私人名稱／查詢
- 參照的狀態／成員／Epic 不存在時提示修正, 不靜默放寬篩選

不增加跨專案任務首頁, 所有入口仍位於使用者選擇的專案中；不產生 GAS 或啟用真實寄信

2026-10-20 介面更新：移除常駐的「全部任務／命名條件」籤列。使用方式：展開「篩選」並設定條件 →「儲存常用篩選」→ 填名稱、選只有我／團隊共用 → 儲存。尚無條件或自訂排序時不提供保存。已保存條件由同一區的「常用篩選」下拉選單套用, 作者可用目前條件更新或移除；「重設篩選」只解除套用並清除搜尋／條件／我的任務或完成範圍, 保留專案、列表／看板、目前排序及保存資料。使用者調整條件後顯示「篩選已調整」, 不默默覆寫原設定；背景載入新版時可按「重新套用」取得新版條件。收合時仍顯示已套用條件摘要及失效警告

視圖網址為 `#/projects/<id>?view=<viewId>`, 任務詳細內容保留 `?view` 以便關閉後回到同一視圖。非作者開私人連結時回到該專案, 只提示找不到可使用的常用篩選；分享「我的任務」依目前登入使用者計算, 不固化建立者 ID

篩選情況提供尚未結案、逾期與未指派。「逾期」只含未結案且到期日早於今天, 取消不列為逾期。多條件與文字搜尋一起採 AND, 我的任務範圍也與其他條件相交
