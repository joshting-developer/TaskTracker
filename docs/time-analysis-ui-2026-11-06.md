# 工時分析畫面整理

日期：2026-11-06（Asia/Taipei）。使用者認為工時分析缺少設計感，這輪調整既有分析入口、三種報表及成員明細的視覺層次。產品指標、API與授權不變。

## 畫面判斷與處理

原畫面先堆疊快速日期、四個篩選、數字、長條與表格，三種分析缺少辨識度；圖表與表格沒有明確分界，平板日期欄太窄，手機趨勢圖須橫向捲動才能讀刻度。判斷來自隔離Seed的Owner／Manager實際登入畫面，不把審美偏好當成已確認產品需求。

- 入口保留三個選擇，以各自的圖形示意區分成員分配、專案比較與時間趨勢；示意SVG是隱藏於輔助技術的裝飾，不代表統計結果。
- 報表上方可直接切換三種分析；快速日期移到標題旁，日期及篩選集中於一個緊湊區塊。沿用已套用範圍及草稿提示。
- 數字保持一組三欄，總投入為主要數字，不新增圖示KPI卡、假成長率或績效指標。
- 成員使用可聚焦的專案堆疊條、姓名首字及對齊的時數；刻度向上取整，使比例與單位易讀。圖例、提示及按鈕名稱保留明確專案文字。
- 專案改用單色直條比較，刻度從零開始，點柱形可查看該專案的成員分配；長專案清單只在圖表內捲動。
- 趨勢使用響應式SVG、HTML刻度及稀疏日期標籤，手機不壓縮字體或強迫整張圖橫捲。可指向日期查看值，也保留原生日期選單供鍵盤及觸控操作；折線與淡色實面來自實際資料，沒有漸層。
- 一般分析表格也加入每頁20筆，圖表及總計仍涵蓋完整期間；沿用既有ReportPagination，沒有改API分頁契約。這是本輪為減少長頁採取的實作選擇，不將先前尚未確認的週／月彙總提前實作。
- 成員工時明細的日期／卡片切換、總量與展開填報統一邊框及留白；保留原本兩層每頁20筆、說明文字安全及返回。

## 設計與使用邊界

依專案ui-ux-pro-max、design-taste-frontend的app-screen及Vue skills，採同一品牌色的小面積資料標記、淡色控制區與規則線。保留使用者已選的紫色品牌及既有側欄；不因上游house style換色或重做全站導覽。

沒有加情緒標語、長篇功能介紹、規則說明或新分析口徑。字型移除原本未載入的Inter宣告，直接使用既有系統字型後備堆疊，不新增外部字型請求；其餘全站CSS未重設。分析頁的主按鈕移除舊陰影，手機內容邊界至少16px。

## 驗證方法與限制

使用本輪獨立tmpfs SQLite API建立示範資料，以Owner與Manager登入；主資料庫不變。比較1440／768／390px，實際操作範圍／切換／圖表聚焦／日期選擇及游標／明細分頁／返回／失敗重試／撤權。

`frontend/tools/time-analysis-seed-check.js`增加20＋8筆翻頁及完整28天圖表／總計不變、游標日期、柱形聚焦；另保留原分析及成員明細專用瀏覽器測試。截圖前將頁面捲回頂端，避免fixed側欄在全頁截圖中出現錯誤位置。

靜態檢查用skill的lint；視覺檢查用登入後實際DOM／CSS匯出的靜態快照交給inspect，補充真人工檢視。靜態快照不驗證互動，互動證據來自真實API瀏覽器；inspect只豁免使用者已確認的紫色品牌，未任意關閉對比或版面規則。

前後截圖在忽略的`frontend/artifacts/time-analysis-before/`及`time-analysis-seed/`；自動檢查與設計sheet在`/tmp/tasktracker-analysis-taste/`，不提交產物。這是本機視覺與操作驗證，不是正式環境部署或真人可用性研究。

## 最終結果

- production build、原工時分析流程、成員明細流程及Owner／Manager Seed流程通過；新增日期游標與專案柱形聚焦、20＋8明細分頁、完整28天圖表及總計保持一致。
- 實際檢視1440／768／390畫面；平板日期完整顯示，手機刻度不換行且圖表不需整體橫捲，沒有整頁橫向溢位。一般明細表仍可在自身區域橫捲，欄位不被刪除。
- skill lint及最終三種分析各三尺寸inspect均0 FAIL／0 WARN；只明確豁免使用者已選的紫色品牌。前三輪依序修正舊按鈕陰影、未載入字型宣告、手機邊界及平板欄寬，未擴張為全站換色或改導覽。
- 純前端變更，不另跑無關的後端套件；既有500KB chunk提醒仍存在。隔離API與假資料結束後清理，不部署或改使用者業務資料。
