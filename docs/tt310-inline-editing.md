# TT-310 完整頁就地編輯

在完整頁按「編輯任務」會把同一頁切成表單, 標題／描述在主欄, 狀態／類型／優先級／負責人／日期／Epic／估時在右欄；手機改成上下排列。列表／看板的快速編輯仍開抽屜

兩種呈現共用 IssuePanel 的表單、MarkdownEditor／圖片、欄位驗證、revision與requestId。inline模式使用section, 不呼叫showModal, 不複製一套寫入狀態或新增API。關係／父任務沿用原本編輯控制與同一保存payload

保存成功後讀回單卡才切回閱讀並把焦點移回標題；讀回失敗保留表單, 上方重新載入改成真正讀取單卡。取消有修改時先確認, 路由與關頁保留原草稿守衛。閱讀元件在編輯時只隱藏, 讓尚未送出的留言不因開編輯而丟失；編輯模式不再額外讀取抽屜的留言／歷史頁籤

## 審查與驗證範圍

- 使用Vue共用表單狀態／props及emit, 不另做完整頁副本；資料與交易契約不變
- 只讀既有單卡、成員／Epic每頁30筆候選與明確開啟的子卡／圖片；沒有Workspace全量載入、額外輪詢或無界關聯預載
- 寫入與保存後單卡讀回仍受目前權限；503重試沿用相同requestId, 409保留原稿與圖片參照, 不自動換revision重寫
- Chrome對隔離MySQL／Laravel驗所有屬性一次保存、真實圖片與預覽、503／連點、真409、取消、返回首頁取消、beforeunload、留言草稿、手機焦點不被保存列遮擋、reader UI／HTTP拒絕及列表快速抽屜
- 三尺寸修前／修後與固定比較保存在忽略的artifacts/tt310, 依Josh持續授權保存核准基準, 不代表逐張人工審閱。截圖只用合成帳號／內容
- 既有browser-check、Markdown、UIUX和視覺flow的入口同步：完整頁用region與取消, modal截圖仍從真正的快速編輯開啟, 不以更換定位器略過行為

本卡不新增API、不改現用資料、不部署runtime；測試命令與結果保存在本卡artifacts及交付留言
