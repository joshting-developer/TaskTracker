# 工時分析實用性 review

日期：2026-11-06。證據來自現行API／介面、隔離SQLite測試及真API登入操作；無真人試用訪談，不宣稱使用者成功率或績效效果。

## 判斷

有保留價值，但原版主要是三張加總表，分析深度不足。總量能回答「填報投入分布」，無法回答「誰效率好」「哪個專案進度落後」「人力是否超載」。缺少排班容量、請假／兼任、完整填報率與交付標準時，這些結論都無從驗證。與其增加數字卡，先讓每頁有不同用途與可追查下一步。

| 原問題 | 影響 | 本輪處理 |
| --- | --- | --- |
| 成員／專案都是總時數、紀錄數與占比，同質性高 | 換頁看不出不同問題，也不知道接著查什麼 | 成員以跨專案堆疊長條呈現，專案以絕對投入比較；點名稱／圖表可帶範圍進另一角度 |
| 成員只有參與專案數 | 同樣100小時，無法辨識集中一案或分散多案 | 新增member-project分鐘聚合，呈現分配而不新增績效分數 |
| 只有表格內短比例條 | 難以快速比較規模 | 圖表直接標名稱、時數及占比；完整表格保留，長清單圖表只顯示前12項 |
| 趨勢只有最高值與首尾日期 | 無中間刻度，也不容易取得某日數值 | 顯示0／中間／最高時數刻度、最高投入日及可鍵盤選取的日期值；零日期保留 |
| Seed僅兩個專案各3筆短期工時、分配近似 | 很難驗證不同成員與專案差異 | 補最近28天、四帳號、七組合法成員－專案分配、週日零日期及不同每日時數 |

## 三頁各自的用途與界線

- **成員投入**：看這段時間每個人的已填報工作分配。用於與成員討論「時間花在哪些案子」，可以點某段專案聚焦；不是忙碌度或效率排行榜，未填報成員不等於沒工作。
- **專案投入**：比較各案消耗的團隊時間，協助定期回顧投入是否符合優先順序；點專案可追查成員組成。沒有預算或估時基準，本輪不能判斷超支／報價／成本，也不加入沒有依據的警示。
- **時間趨勢**：觀察填報投入的變化與集中日期，回頭核對工作安排或補登狀況。沒有填報的日子顯示0，不能直接當成出勤缺失或績效降低。按實際workDate而非建立時間統計。

如果團隊之後並不持續填工時，這三頁的價值會很低；建議試用時用實際一至兩週紀錄檢查是否有用，而不是繼續加指標。本輪保留原三入口與名稱，不擅自新增成本、效率、容量、同比或預估準確度分析。

## 呈現及互動選擇

沿用現有品牌、平整工作區與三個分析入口。TimeAnalysis負責API、已套用／待套用篩選與錯誤；TimeDistributionChart只接已授權聚合與發選取事件；TimeTrendChart負責日期點選值，沒有第二套API或共享狀態。表格提供精確資料與無障礙替代，圖表不僅靠顏色辨識。

點選圖表會以目前**已套用**的日期範圍聚焦成員／專案，不偷偷把未套用的日期草稿帶入。仍維持原篩選AND、分類內加總、失敗清舊結果與撤權清畫面。新增「本月／近28天」快速範圍供一般查詢與seed比較，不保存視圖、不新增首頁小工具。

類別比較採長條、時間序列採折線；依專案UI／UX skills的圖表比較與app-screen規則選擇，不加無用途圓餅／雷達／儀表。少量／空資料不畫假趨勢。手機趨勢圖在區塊內橫向捲動，確保刻度可讀，整頁不溢出。

## Seed與保護

`database/seeders/DemoSeeder.php`集中所有示範資料。DatabaseSeeder呼叫它；標準`db:seed --class=DemoSeeder`與相容`tasktracker:seed-demo`皆可使用，後者提供明確reset選項。Seeder的run／seed／loadProject入口在讀寫前檢查環境，只允許local與testing，production／staging等即使加--force仍拒絕；原loadDemo API在重試回放前也先驗環境。Services不再放DemoData／DemoService／DemoTimeData，ProjectAclUpgrade不再包含示範帳號／權限配置。

DemoSeeder在既有f-ws的FIRST／SECOND專案補分析資料；新建seed包含原6筆與新增168筆（完整四週、每週6天、7組合法分配）。角色名稱只決定示範資料的預置分配，能否寫入仍由有效permission／scope驗證。developer不會因此取得second權限。

依伺服器Asia/Taipei今天往回28天，週日不補示範、每日起伏刻意保留。部分工時直接填Epic，其餘Task／Bug，不重複累計Epic彙總。每月首次seed建立快照；月內重跑不追加後續天數、不補回使用者刪改／作廢的資料。工作日標記避免下月重疊期間重複灌入；仍採每日24h上限，已達上限、停用或無權限成員會略過，不改現有資格。

這是**本機示範資料**，不是自動業務排程；新增工時會進入f-ws統計與月曆。只在local／testing，保留密碼、卡片、作者與舊紀錄，不使用reset，不改其他Workspace。當月標記一旦建立即不因後續授權變動自動補缺漏。若找不到FIRST／SECOND，跳過分析seed，不擅自重建使用者刪掉的專案。reset仍僅重建原seed namespace，會按原授權清掉此空間資料，不在本輪使用。

## 後續值得做但本輪不製作

1. 若確認要追成本：先設計專案工時預算、計費口徑與修改歷史，再做預算對實際。
2. 若要看容量：先有每人可投入時數、休假與兼任範圍，再判斷負荷，不能拿24小時填報上限當容量。
3. 若要驗證估時：先定義結案範圍與估時基準版本，避免把尚未完成的卡片拿來算準確度。
4. 真正需要稽核時再做原始工時明細／匯出；本輪圖表不回傳說明、Email或私有內容。
