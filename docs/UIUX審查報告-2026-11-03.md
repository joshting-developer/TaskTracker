# TaskTracker UI／UX 審查報告

日期：2026-11-03（Asia/Taipei）｜對象：目前 Vue／Vuetify 前端及真實 Laravel API 操作流程。

**結論：目前的專案入口、清單／看板分工與側欄操作可以保留。優先修可讀性、首頁待辦與專案入口的競爭，以及表單錯誤回饋；不需要先換一整套視覺風格。** 本輪只審查, 未修改產品 UI。下列改善均是助理建議, 尚未視為使用者採納。

## 3. 已確認問題與優先順序

P1：影響主要入口或閱讀, 建議下一階段先處理。P2：可操作, 但效率／理解／鍵盤體驗有缺口。這是本專案的修正優先級, 不是安全漏洞或合規等級。

### U01 · P1：次要文字過淡, 部分重要說明只有 10px

**重現與證據：** owner 進通知預覽, 收件人／時間實際是 `10px`, `#b0a0be` on white, 量測約 **2.4:1**。SMTP 說明 `#b4a1c5` on `#f2edf9` 約 **2.1:1**。工時 Epic 估時說明約 2.6:1, 狀態設定底部說明約 2.7:1；登入說明約 3.3:1。截圖也能直接看出淡字, 不是只看 stylesheet 的舊規則。

**影響：** 收件對象、時間、SMTP 限制及估時資訊難讀, 特別是手機與長時間使用。字小和顏色淡同時發生。

**最小改善：** 將實際資訊統一到 secondary text token, 一般閱讀先以 14–16px、metadata 12–13px 為目標；依 skill 的一般文字 4.5:1 檢查線確認實際背景。disabled 控制另處理, 不把不需操作的唯讀資料一起降透明度。保留既有紫色主色。

**位置：** [styles.css](../frontend/src/styles.css) 的 `.notification-meta`（158 行）、`.smtp-card small`（154 行）、`.report-epic > span`（134 行）, 及各頁繼承的字色。證據：`notifications-1440.png`、`time-390.png`、`statuses-1440.png`、`login-390.png`。

**來源：** Pro Max 可讀性／對比；Taste §9 type and colour。

### U02 · P1：首頁小待辦無上限, 推走原本的專案入口

**重現與證據：** owner 首頁只有四筆尚未完成待辦。1440×900 下「我的專案」標題 y≈734, 首張專案名稱 y≈968；390×844 下標題 y≈807, 專案名稱 y≈1038。專案名稱及進入按鈕均在第一屏之外, 待辦增加會繼續往下推。側欄仍將整頁標示為「專案列表」。

**影響：** 回首頁原本是為了換工作空間／專案, 現在要先越過個人工作清單。首頁同時有兩個主要工作, 沒有空間分配上限。

**最小改善：** 先讓專案入口可立即到達, 小待辦預覽限量並可展開；或把首頁明確分成「我的工作／專案」兩個區域或 tab。兩者是待選方案, 本輪不先做新版首頁或恢復儲存視圖。

**位置：** [App.vue](../frontend/src/App.vue) 439–441 行, TodoHome 排在專案標題與 ProjectHome 前；[TodoHome.vue](../frontend/src/components/TodoHome.vue) 的 `openItems` 全部渲染。證據：`home-1440.png`／`home-390.png` 及 `results.json` headings 座標。

**來源：** Taste §2.2 one question、§7.8 overview、§10 density；Pro Max 導覽與資訊層級。

### U03 · P2：工時／設定等功能沒有獨立網址, 重整會換畫面

**重現與證據：** first → 工時月曆 → 瀏覽器重整。重整前後 hash 都是 `#/projects/<first-id>`, 月曆 region 數量從 1 變 0, 任務搜尋出現。畫面回到任務列表。程式中的狀態、成員、通知等 `changeSection()` 也只更新記憶體並 replace 同一 Project hash。

**影響：** 無法直接書籤／分享目前功能, 重新整理或重新開啟失去工作位置。這是目前功能導覽缺口, 不是建議新增分析功能。

**最小改善：** 給既有 section 穩定路由並處理返回／深連結、ACL 及未儲存表單保護；保留目前 issue／board URL 相容。不用同時改寫整個 App 或換框架。

**位置：** [App.vue](../frontend/src/App.vue) 164 行 `changeSection()`、266 行 `readHash()`。證據：`follow-up.json` 的 refresh before／after。

**來源：** Pro Max 導覽；Taste app shell 與 settings one view per area。

### U04 · P2：看似 tab 的元件沒有完整鍵盤切換

**重現與證據：** 在首頁把焦點放「我的待辦」, 按 ArrowRight, 焦點及選取都仍停原 tab。兩個 tab 都是 `tabindex=0`, 沒有 `aria-controls` 或對應 tabpanel。按 Tab／Enter 仍可切換, 因此不是完全無法使用。完整頁活動 tab 雖有 panel 關聯, 也未提供方向鍵處理。

**影響：** 對使用 tab 模式的鍵盤／輔助科技使用者, 預期與實際操作不一致。

**最小改善：** 若維持 ARIA tab, 補 roving tabindex、方向鍵／Home／End 及 panel 關聯；或改成語意正確的普通切換按鈕組。任務狀態目前是 `role=group`＋`aria-pressed`, 是修改資料的動作, 不必為外觀一致而硬改成內容 tab。

**位置：** [TodoHome.vue](../frontend/src/components/TodoHome.vue) 65 行；[IssueDetail.vue](../frontend/src/components/IssueDetail.vue) 活動區；[IssuePanel.vue](../frontend/src/components/IssuePanel.vue) 記錄 tab。直接重現為首頁, 其餘兩處由原始碼確認相同缺口。證據：`tab-keyboard.json`。

**來源：** Pro Max Keyboard Navigation／Focus States。

### U05 · P2：工時錯誤有顯示, 但沒準確指出規則及欄位

**重現與證據：** 選有效 Task, 投入小時填 `0.017`, 按登記。會顯示「請填入至少 1 分鐘的工時, 可用 0.5 表示半小時」。0.017 小時其實是 1.02 分鐘, 真正失敗原因是不能換算成整數分鐘。錯誤只在表單上方, 沒有 `aria-invalid`／欄位錯誤關聯, 焦點仍在送出按鈕。已存在 `role=alert`, 不能說完全沒有錯誤公告。

**影響：** 使用者照文字理解「已超過一分鐘」仍不知如何改正；鍵盤使用者需自行找欄位。所有表單錯誤都搬焦點也不理想, 應依提交結果統一設計。

**最小改善：** 明確說「工時以整數分鐘計算」及可接受例子；錯誤緊鄰投入欄位, `aria-describedby` 連回訊息, 提交失敗定位首個錯誤或摘要。可考慮小時＋分鐘輸入, 是替代提案而非已確認需求；不需先裝表單套件。

**位置：** [TimeCalendar.vue](../frontend/src/components/TimeCalendar.vue) 70–75 行及填報表單。證據：`time-invalid-390.png`／`error-focus.json`。

**來源：** Pro Max Error Placement／Focusable Error Summary；Taste §8 forms、§11 errors。

### U06 · P2：手機任務詳情優先展示整塊屬性, 打斷閱讀

**重現與證據：** 390px 詳情頁順序為標題 → 類型／優先級／負責人／日期／Epic／估時等 → 描述。可編輯帳號的描述標題約 y≈630, 活動區在更下方；reader 同樣先讀一整塊屬性。Desktop 的主內容／右側屬性分工較清楚。

**影響：** 日常進卡看描述與討論要先滑過相對穩定的 metadata, 看起來像在讀設定表。現有範例描述為空, 還不能當成長描述閱讀測試已完成。

**最小改善：** 手機先標題／狀態／描述, 顯示少量常用屬性, 其餘可展開；保留負責人與狀態的快速辨識。reader 的目前狀態可用清楚的唯讀標籤, 不必整排淡化 disabled 按鈕。

**位置：** [IssueDetail.vue](../frontend/src/components/IssueDetail.vue) 149 行以下 mobile rules, properties `order:1`、body `order:2`。證據：`issue-detail-390.png`／`reader-detail-390.png`。

**來源：** Taste §4 canvas、§12 phone；Pro Max responsive hierarchy。

### U07 · P2：平板看板工具列文字被擠成直排

**重現與證據：** 768px 寬, 左側 sidebar 仍占 215px；工具列中「泳道」「卡片」各換成上下兩個字。量測 label 剩餘文字寬約 13px, select 本體仍正常。手機 700px 以下才改直向排列, 因此 768px 成為斷點間隙。

**影響：** 工具列像壞掉的排版, 也壓縮真正看卡的空間。看板自身可橫向捲動是必要工作方式, 不應因此列為整頁 overflow 問題。

**最小改善：** 工具列依實際可用寬度 wrap／換行, label 不拆字；可考慮在平板先收 sidebar。不要僅縮小文字。驗收補 768／1024 及 sidebar 展開／收合狀態。

**位置：** [ProjectBoard.vue](../frontend/src/components/ProjectBoard.vue) 47–49 行及 86–89、118 行樣式。證據：`board-768.png`／`follow-up.json` board rectangles。

**來源：** Taste §12 中間尺寸；Pro Max responsive／text overflow。

### U08 · P2：手機小待辦的完成／更多入口偏小

**重現與證據：** 390px 首頁的完成 checkbox 實際 18×18px, 「更多」summary 約 40×20px；文字標題與完成控制是不同動作, 點標題會展開說明, 不會完成。操作本身可用, 但手指目標小。

**最小改善：** 增大點擊容器而保留小圖示外觀；優先處理完成、退回等常用動作。可用 44px 作本產品觸控設計目標。這是 skill 的舒適目標, **沒有逐一驗證鄰近間距例外, 不宣稱 18px 就必然違反網頁 WCAG**。

**位置：** [TodoHome.vue](../frontend/src/components/TodoHome.vue) `.todo-row > input` 及 `.todo-actions summary`。證據：`home-390.png`／`results.json` smallControls。

**來源：** Pro Max Touch & Interaction；Taste §12 phone。

## 4. 值得保留、風格偏好與誤報處理

**已觀察的優點：** 任務清單與看板是分開入口；類型直接顯示 Epic／Task／Bug, 狀態有文字；篩選按需展開, 手機也可操作。看板除了拖曳, 已有逐卡狀態 select, 並實際保存成功。轉卡會帶入小待辦內容、要求選有權限專案, 完成後打開正式卡片；日期點擊會開工時側欄。手機導覽可收合且 Escape 能關閉。這些比新增裝飾或 KPI 更值得維持。

**角色差異：** owner／manager 可見 first＋second, maintainer 可見兩個指定專案但沒有建立 workspace Project 入口, developer 只見 first。reader 沒有新增／編輯／工時入口；未加入專案者有明確說明, 不呈現其他專案卡。這是畫面層的觀察, 不是本輪重新完成後端 ACL 安全稽核。

**可再整理的文案：** 所有角色的 Workspace 入口都寫「管理與邀請」, 一般 user 實際不能邀請；有些頁仍有英文 eyebrow、返回專案列表、Project 大標題與功能標題的多層介紹, 佔據首屏。建議之後依權限改成「成員」或「管理與邀請」, 並沿用任務清單已簡化的頁首, 不急著全部拿掉。這些是次階段建議, 本輪沒有把所有文字都當缺陷。

| 工具警告 | 本輪判斷 |
| --- | --- |
| `palette-purple`、深色側欄禁用、彩色 Project icon | Taste 明言部分是作者 taste。紫色與側欄不是已證明的操作缺陷, 不自動換品牌 |
| `heavy-shadow` 出現在任務抽屜 | app 規則允許真的 overlay 浮起；不把 dialog shadow 誤當普通卡片問題 |
| `font-fallback` | 指出使用系統 fallback 的情況, 不代表繁體中文一定無法閱讀。沒有要求載入外部字型或改 Inter |
| `below-fold` 在工時月曆 | 詳細分析排在月曆下方可合理, 不要求所有報表塞進首屏；首頁專案入口另由產品主要工作判斷 U02 |
| static `emoji`／`glass`／`shadow` | 27 個 source 檔共 26 條：emoji FAIL 2、eyebrow WARN 15、shadow WARN 8、glass WARN 1。含隱藏區與 overlay, 逐項對照實際用途, 不等於 26 個產品 bug |
| 頁面大標題／小 metadata | 用途不同, 不把登入宣傳標題或所有 12px 欄位一概視為失敗；U01 只列實際資訊的可讀性問題 |

## 5. 建議下一階段怎麼修

1. **先做可讀性與表單回饋**：U01＋U05, 統一文字 token、錯誤規則與欄位關聯, 保留現有布局及草稿保護。
2. **收斂首頁主次**：U02, 選定待辦預覽限量／展開或首頁分區方式, 再處理 U08 觸控目標；不新增儲存視圖或分析儀表板。
3. **穩定導覽與跨尺寸**：U03／U04／U06／U07, 以獨立功能路由、正確鍵盤模式及手機閱讀順序補齊, 各自可驗證提交。

建議之後兩個 skill 繼續搭配：Pro Max 當操作檢查表, Taste 當資訊布局與實際畫面的第二視角。色彩、欄位密度、tab 是否適合仍由 TaskTracker 的使用情境決定, 不把上游 house style 全盤當產品規格。
