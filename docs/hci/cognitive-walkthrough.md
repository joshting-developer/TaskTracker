## 方法與證據界線

實際使用 production build、隔離 Laravel API、全新暫存 SQLite。操作情境為 owner、developer、受邀的新成員；新成員先無 Project、再 first 的 reader、最後改 developer。沒有使用真人參與者, 沒有把角色模擬當訪談或成功率。AI 已熟悉程式, 無法代表真正第一次使用者；先觀察可見入口與畫面, 再追查相關程式, 以「觀察」和「可能風險」分開記錄。

完成 T1–T8 任務的主路徑與指定變體, 共 45 份畫面／狀態快照, 未捕捉到 JS pageerror。桌面 1440×900、手機 390×844；本輪未另測平板。起始資料為兩個 Project、14 張 Issue、6 筆工時；另由 UI 自記／交辦、轉卡及邀請, 以 fixture API 補八筆交辦用來測通知與三筆預覽。

每一列依上游要求回答四題, **答案是審查者判斷**, 不是觀察真人後的統計：

- Q1：能否形成下一步的正確目標？
- Q2：注意得到正確動作嗎？
- Q3：看得懂此動作與目標的關係嗎？
- Q4：做完後的回饋是否能理解？

符號：✓＝有清楚線索且實際走得通；△＝行為可完成但線索／理解存在疑點；✗＝實際有中斷或回饋缺口。不用符號總和計算 UX 分數。每列最後提供對應證據與最小建議。

本機證據在忽略的 `frontend/artifacts/usability-audit-2026-11-04/`, 下列名稱均對應 `<名稱>.png` 及 `observations.json`。截圖不提交, 所以報告同時記錄關鍵行為與數值。建議的真人題目及完成條件見 [計畫與腳本](usability-test-plan-2026-11-04.md)。

## 最可能出問題的步驟與建議順序

1. **T2步驟4–5：看不見的草稿會讓另一 tab 的操作消失。** 實際可重現, 優先使草稿狀態與恢復路徑可見。F03。
2. **T1步驟5／T5步驟5：中斷後的查閱範圍重設。** 目前功能網址已穩定, 下一步是保留目前範圍／條件；不等於恢復使用者已移除的「儲存視圖」。F01。
3. **T2步驟3：手機快速記錄入口在專案區之後。** 專案優先有合理性, 但速記應有直接入口；先用真人任務比較可發現性, 不再單向把其中一區全部往上搬。F02。
4. **T1步驟3：閱讀工作先遇到編輯表單。** 可試明確閱讀入口／閱讀預設＋顯式編輯, 但實際偏好需要驗證, 暫列次要。F04。

主要工作沒有出現整段無法繼續的 blocker；發現集中在上下文保存及隱藏狀態, 不是要求再加更多功能。完整問題證據、程度與真人資料缺口見 [可用性 findings](usability-findings-2026-11-04.md)。
