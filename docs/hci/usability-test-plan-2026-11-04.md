# TaskTracker 任務走查與真人試用腳本

日期：2026-11-04（Asia/Taipei）。本輪實際執行為 AI 輔助任務走查；真人參與者 0, 未進行主持／非主持式真人研究。這份計畫在瀏覽器走查前建立, 後續結果另記報告。

## 範圍與方法

套用 cognitive-walkthrough 的逐步四題：Q1 是否形成目標、Q2 能否注意正確動作、Q3 是否理解動作與目標關係、Q4 能否理解結果。回答是 AI 判斷, 不是使用者訪談。以 usability-testing 的任務界線、角色、觀察及資料缺口規範整理；不以腳本跑通當真人成功率。

使用 production build／隔離 Laravel SQLite／假 seed 帳號, 不碰主服務資料。桌面 1440×900, 手機 390×844, 必要時平板 768×1024。可用 API 建立資料／核對結果, 走查中必須經實際可見入口操作。已熟悉專案的 AI 不能自稱完全陌生的新手, 將實測狀態與可發現性假設分開。

## 任務及觀察者完成條件

| ID | 角色與起點 | 給參與者的情境目標 | 觀察者完成條件 |
| --- | --- | --- | --- |
| T1 | developer, 登入後首頁 | 找到 first 裡交給你的工作, 看懂其中一件的要求及進度 | 正確專案／本人工作／任務描述與狀態, 不能用內部網址直接跳過入口 |
| T2 | owner／developer, 首頁 | 記下一件自己的小事, 再把另一件交給指定同事 | 正確本人／對方, 有保存與收到的回饋, 不誤建正式任務 |
| T3 | developer, 收到的小待辦 | 這件小事需要團隊正式追蹤, 安排進 first | 發現轉卡、專案與欄位填寫、保存與來源去向；錯誤不丟草稿 |
| T4 | developer, first | 看正在處理的工作, 更新剛做完的一件 | 可找到看板／狀態操作, 狀態保存, 回列表可確認 |
| T5 | developer, first | 記下今天處理某件工作的半小時, 再修正或找回紀錄 | 日期入口、選卡、單位、保存與本人修改；觀察整數分鐘錯誤 |
| T6 | developer, 其他畫面 | 從交辦通知找回一件較舊的事, 中斷後繼續處理 | 超過三筆預覽仍可定位, 能返回／重整, 不丟未保存內容 |
| T7 | 受邀者／reader | 加入團隊並閱讀指定任務, 看懂目前進度 | 未授權空狀態不誤認為丟資料；授權後能看描述, 唯讀可辨識 |
| T8 | owner, 首頁 | 讓新同事只參與 first 的工作, 不開放 second | 邀請與 Project 成員授權分工, 正確資格, 可在另一帳號核對 |

每個角色的判斷依有效 permission。正常／無資料／無權限／驗證錯誤／未保存離開為本輪核心狀態；大量資料另外有限抽樣, 不是所有功能壓力測試。

## 真人試跑時使用

建議分三組, 每人 3–4 題：一般協作者 T1／T2／T3／T5；回訪協作者 T4／T5／T6；管理與閱讀 T8／T7（分角色）。這是招募建議, 未有人接受試用。先一兩次試跑調整題目與資料；同事若就是目標使用者可以參與, 但記錄是否曾參與開發。

只念情境目標, 不念完成條件或畫面標籤。開場說明「我們測的是產品, 不是你；卡住請說出在找什麼」。不教正確位置、不替設計辯護。若需要協助則記提示內容, 不把協助後完成算獨立完成。錄製前先說明用途並取得同意, 本輪未聯絡／錄製任何人。
