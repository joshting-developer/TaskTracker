# 第三方 API 文件與 AI Agent 整合指南規劃

日期：2026-11-12  
狀態：**已確認方向，規劃文件；尚未實作公開 PAT API、文件站或 Agent 連接器。**

## 目的與開發順序

TaskTracker 的既定順序為：

1. 先完成效能與穩定性：分責查詢、SQL 索引與測試、移除過量載入、正式部署拓樸量測。
2. 再完成第三方整合基礎：個人 PAT、有效 Scope／期限／撤銷、公開 REST API，以及**可供人與機器使用的 API 文件**。
3. 上述基礎經外部客戶端驗收後，再擴充產品功能。

**核心成果：** 外部使用者或工具只需讀取文件、取得合法授權，就能直接查詢、建立、更新、留言及追蹤 TaskTracker 卡片，不必經由手動複製指令、瀏覽器操作，或特定 AI 的專用轉接服務繞一圈。

預期使用方包含 ChatGPT（透過其支援的連接器／自訂整合）、Multi-Agent VS Code 插件、Codex／Claude 外部工具、CLI、GitHub Actions、n8n、Discord Bot 與其他 HTTP 客戶端。**API 與文件不代表這些產品自動取得連線能力**：每個客戶端仍須具備可呼叫 API 的連接器／工具能力，並經使用者授權提供憑證。TaskTracker 只提供工具中立、可驗證的標準契約。

本文件補足 [API-first 平台架構](api-first-platform.md) 的文件交付與驗收要求；既有 Session／REST／權限及資料存取語意以該文件與 [分責查詢 API](query-api-v1.md) 為準，不在此建立第二套業務規則。

## 文件交付物與建議入口

下列 URL 為**建議，不是目前已存在的路由**；實際前綴、版本與公開方式在實作卡確認。

| 入口（建議） | 對象與目的 | 必要性 |
| --- | --- | --- |
| `/docs` | 開發者入口，快速開始、認證、API 分類、版本與錯誤處理 | 必要 |
| `/openapi.json` | OpenAPI 3.1.x 機器可讀規格，供客戶端、工具產生器與 AI Agent 解析 | 必要 |
| `/api/docs` | Swagger UI 或等效互動式 API Explorer，從同份 OpenAPI 產生 | 建議 |
| `/docs/authentication` | PAT 建立、保管、Scope、到期、撤銷與權限交集 | 必要 |
| `/docs/examples` | cURL 與至少一種常用程式語言的完整工作流程 | 必要 |
| `/docs/agents` | 簡潔的 AI Agent／外部工具整合指南（可取得 Markdown 原文） | 必要 |

- OpenAPI 規格要能以固定 URL 被**未登入的文件閱讀者**取得；提供規格不代表開放未授權的業務 API。
- 規格中的 `servers` 指向受支援的 API Base URL；避免把本地開發地址或私有部署拓樸當作正式範例。
- OpenAPI 版本以實際工具鏈相容性選定，優先考慮 3.1.x；不要把未實作的端點加入正式規格並宣稱可用。
- Swagger UI 是閱讀與測試介面，不是新的業務服務；如提供 Try it out，不得將 PAT 寫入網頁原始碼、日誌或永久儲存。
- 文件入口可獨立部署或由 Laravel／前端提供；不為文件特別新增常駐基礎服務，除非量測與需求證明必要。

## 每個 API 的最低文件契約

每個正式公開的 endpoint 至少須具備：

1. **用途與版本**：method、path、穩定 `operationId`、tags、用途、常見使用情境與保留／棄用狀態。
2. **認證與權限**：Bearer PAT、安全方案、所需 read／write Scope、Workspace 綁定與對應 Project／資源的有效 permission；不得僅因 Token 有 write 就跳過伺服器有效權限。
3. **輸入**：Path／Query／Header／Body 的型別、必填、限制、預設值、搜尋與排序規則、完整 Request 範例。
4. **輸出**：成功碼、實際 JSON Schema、列表與詳細投影差異、分頁欄位與 Response 範例，不讓摘要冒充可編輯的完整資料。
5. **失敗情況**：401 無效／過期／撤銷、403 已知但權限不足、404 不可見或不存在、409 資格／revision 衝突、輸入驗證錯誤，以及適用的限流錯誤；狀態碼與錯誤結構須以實作契約為準，不預設所有路由一律回 422。
6. **寫入一致性**：當前 `revision` 的取得、版本衝突重讀流程、`requestId` 冪等／重試規則；網路逾時不能盲目重新產生另一個建立請求。
7. **效能與安全限制**：分頁上限、資料範圍、資料量成長行為、是否會觸發副作用；不存在的費率或限流數值不應憑空寫入文件。

不要把本機 Session＋CSRF 的呼叫方式誤寫為 Bearer PAT 的第三方使用方式；公開 API 需要不依賴瀏覽器目前 Workspace Session 的明確授權上下文。既有業務邏輯仍共用 Application Service／集中授權／資料存取與交易，不複製另一套寫入規則。

### PAT 既定規則（引用現有決策）

- 第一版 Scope 為 `read`／`write`，`write` 隱含 `read`；Scope 清單化，之後可擴充細項。
- PAT 綁定單一 Workspace，預設一個月，最長兩年，無永久 Token；過期不可延長，須重新建立。
- Token 原文只在建立時呈現，伺服器只保存安全雜湊；支援撤銷，撤銷或過期後不可再呼叫。
- 有效操作權限 = PAT 能力 ∩ 使用者目前有效 permission ∩ Token Workspace／目標 Project 與資源條件。
- 第一版不因第三方 API 文件需求新增刪除／封存能力；現有狀態 `closed` 與後續 TT-250 定義保持一致。

## AI Agent 整合指南應說明什麼

`/docs/agents` 應面向**第一次接觸 TaskTracker、沒有原始碼存取權**的外部客戶端，以最小上下文解釋：

- 如何發現 `/openapi.json`、驗證支援版本、取得 API Base URL 與認證方式。
- 核心模型：Workspace → Project → Issue／Todo，哪些資源需要指定 Project 範圍、哪些有獨立權限。
- 依卡號／identifier 精準定位；如何取得最新詳細資料與 `revision`，不要把列表摘要當作編輯依據。
- 建卡、查詢、更新、留言、回報進度的最短流程；如何處理分頁、409、重試、撤權及權限變動。
- 不把使用者的 PAT 印在對話、Commit、卡片、網址、Prompt、可讀 log 或範例檔內。
- 呼叫外部寫入或修改卡片前，遵循執行環境與使用者授權；文件只是教學，不授予 Agent 自主操作權限。
- OpenAPI 為正式機器契約，Agent 指南是輔助解說；後續文件更新不得使兩者互相矛盾。

TaskTracker **不內建 MCP Server、模型專用 Skill、Multi-Agent 編排器或自動讀取外部 AI 對話**；外部工具可依自己的執行平台使用 OpenAPI 建立 Adapter。需由 ChatGPT 直接開卡時，仍須 ChatGPT 可用的整合／工具與授權存在，不能只憑公開文件就自動執行。

## 外部端到端驗收：無須閱讀原始碼即可完成一張卡

用隔離環境、人造資料、權限最小化的測試 PAT，讓一個**沒有 TaskTracker 原始碼、只看公開文件**的通用 HTTP 客戶端依序：

1. 取得文件入口與 OpenAPI，知道怎麼填 Bearer PAT、選擇可見的 Project。
2. 查詢可見 Project、任務／狀態候選，依文件建立新 Issue；重試同一 `requestId` 不重複建立。
3. 依卡號精準查詢剛建立的 Issue，取得最新詳細與 `revision`。
4. 更新狀態／內容並新增留言；遇 409 時依文件重新取得最新版再決定是否重試。
5. 查詢任務以驗證更新成功，並依現有服務規則更新進度／完成狀態。
6. 驗證只有 read 的 PAT 不能寫；不同 Workspace／不可見 Project 不洩漏資料；撤權、過期及撤銷後的 Token 立即失效。
7. 由文件讀者完成全部操作，不依賴人工補充未公開的路徑、Cookie、內部欄位或特殊 SQL／RPC；記錄實際請求、回應和卡住的文件缺口。

首輪允許只驗收讀取、建立、更新與留言等已有業務語意的功能；**不為了湊 CRUD 而先開放刪除**。Webhook、批次、外部識別及 Multi-Agent 專用功能不屬本項前置驗收。

## 文件與實作同步策略

- OpenAPI 規格應有單一可信來源（由程式／註解產生或 spec-first 均可，實作卡依工具鏈選定），**不能手寫一份又自動產生另一份彼此分歧的正式規格**。
- CI 至少驗證 OpenAPI 格式、路由／operationId、Schema、必填、安全方案與範例有效性；關鍵端點以 Contract Test 驗證實際 HTTP 回應及錯誤碼。
- API 欄位、URL、權限、狀態碼、分頁與重試語意變更時，**同一張實作卡**同步更新 OpenAPI、指南、範例、測試及必要的 migration／deprecation 註記。
- 文件示例只用人造資料；不提交真實 PAT、Cookie、個資或內部伺服器配置。確保公開文件及 `openapi.json` 不暴露私有操作或未開放端點。
- 適用既有 [八項資料存取審查](../skills/tasktracker-development-standards/references/data-access.md)；文件不是代替授權、測試與正式部署效能驗證。

## 完成定義（Definition of Done）

**第三方整合階段不可只以 API 路由可呼叫就宣稱完成。** 至少應同時滿足：

- [ ] 效能／資料存取前置問題達當期驗收門檻。
- [ ] PAT／權限／到期／撤銷及基本公開讀寫 API 可用。
- [ ] 正式 OpenAPI 端點、開發者文件、認證指南與 Agent／CLI 指南可取得。
- [ ] 文件中的範例可被獨立客戶端實際執行，Contract Tests／CI 驗證通過。
- [ ] 外部客戶端只憑文件及合法授權完成「查專案 → 建卡 → 讀卡 → 更新 → 留言 → 驗證」流程。
- [ ] 越權、撤權、重送與版本衝突均有可驗證的行為和文件。
- [ ] API 文件與實作由同一交付流程維護，未完成或未支援功能明確標記。

此階段完成後，才適合將 ChatGPT／Multi-Agent 的「直接開 TaskTracker 卡片」作為正式整合流程；在那之前只把它視為產品目標，不宣稱目前已可直接操作。
